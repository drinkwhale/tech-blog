# Creed Blog Style

`sketchofcreed.tistory.com`(크리두 Story) 글 8편을 분석해 추출한 스타일 규칙. 핵심 특징은 **이모지로 구획한 섹션 + 산문 최소화 + 실제 설정값 노출**이다.

## When to Activate

- Ops·Cloud·Kubernetes 운영 지식을 정리하는 글
- 특정 제품·기능의 설정 옵션·모드·비용을 정리하는 글 (예: Terway CNI, MSE, Loki-Tempo 연동)
- 공식 문서를 읽고 실무 관점으로 재정리하는 글
- 도구 입문 글 (예: n8n 기본 개념)

**이 스킬을 쓰지 않는 경우:**

- 트러블슈팅·사고기록 → `archetypes/default.md` STAR 템플릿
- Mermaid 다이어그램 중심 개념 설명 → `tech-concept-post` 스킬
- 장문 에세이·voice 중심 → `article-writing` 스킬

## 스타일 규칙

### 1. 이모지 섹션 헤더 (필수)

모든 `##` 헤더는 이모지로 시작한다. 관용 매핑:

| 이모지 | 용도 |
| --- | --- |
| 💬 | TL;DR·한 줄 요약 |
| 🔍 | 개요·개념 설명 |
| ⚙️ | 설정·구성·옵션 |
| 🛠️ | 실습·예시 |
| 🔗 | 데이터 흐름·연동 |
| 📋 | 옵션 표·정리 |
| 🎯 | 검증·확인 방법 |
| ⚠️ | 주의사항·삽질 기록 |
| ✅ | 하위 확인 항목 |
| 🔚 | 요약·마무리 |
| 📚 | 참고 자료 |
| 1️⃣~9️⃣ | 순차 진행 글의 섹션 번호 |

하위 구획에는 `🔹` 을 불릿 대신 사용해도 된다.

### 2. 불릿 우선, 산문 최소

- 문단(3줄 이상 산문)은 섹션당 최대 1개
- 나머지는 전부 불릿 또는 표
- 불릿 형식: `**항목:** 설명` 또는 `항목: 설명`

```markdown
✅ 좋음
- **파드 밀도:** 노드당 수백 개 파드 배포 가능
- **제약:** 클러스터 생성 시에만 Terway 선택 가능

❌ 나쁨
Terway는 파드 밀도가 높아 노드당 수백 개의 파드를 배포할 수 있습니다.
다만 클러스터를 생성할 때만 선택할 수 있다는 제약이 있습니다.
```

### 3. 종결어미 — 2가지를 섞는다

| 맥락 | 종결 | 예시 |
| --- | --- | --- |
| 개념 설명 문장 | `~입니다 / ~합니다 / ~됩니다` | "이 필드는 Grafana Explore 탭에서 표시될 이름입니다" |
| 불릿 항목 나열 | 명사형 (`~가능`, `~지원`, `~필요`) | "각 파드에 개별 ENI 할당" |
| 필수 조건 | `~해야 합니다` | "로그에 trace_id 문자열이 포함되어 있어야 합니다" |

한 글 안에서 문장은 `~입니다`, 불릿은 명사형으로 일관되게 유지한다.

### 4. 표는 최소 1개

- 옵션·모드·비교가 있으면 반드시 표로
- 2열 (`옵션 | 설명`) 이 기본, 도구 비교는 3~4열
- 표 위에 설명 문장 1줄

### 5. 코드블록은 실제 값으로

- 플레이스홀더(`<YOUR_VALUE>`) 대신 실제 동작하는 값 사용
- 언어 태그 명시 (` ```yaml `, ` ```bash `)
- 주석으로 핵심 라인 표시

### 6. 구분선

섹션 사이에 `---` 삽입. 시각적 구획이 이 스타일의 핵심.

### 7. 길이

- **1,800 ~ 3,500 단어** (한국어 기준 3,000~6,000자)
- 섹션 6~9개

## 금지 패턴

- "최근 급변하는 환경에서", "혁신적인", "강력한", "게임체인저"
- 출처 없는 수치·통계 (원문 /88은 CVE·CVSS 수치에 Wiz 리서치 출처를 명시함 — 이 기준 유지)
- 섹션을 끝내는 "~에 대해 알아보겠습니다"
- 이모지 없는 `##` 헤더
- 3줄 이상 산문이 연속 2문단 이상

## Quality Gate

발행 전 체크:

- [ ] 모든 `##` 헤더에 이모지 있음
- [ ] TL;DR 2~3줄
- [ ] 표 1개 이상
- [ ] 코드블록에 실제 값 사용 (플레이스홀더 없음)
- [ ] `⚠️ 주의사항 / 삽질 기록` 섹션 있음
- [ ] `📚 참고 자료` 링크 4개 이상
- [ ] 섹션 사이 `---` 구분선
- [ ] 작성 체크리스트 등 내부 메모가 본문에 남아있지 않음
- [ ] `hugo server -D` 빌드 오류 없음
